# LifeKernelOS 产品需求文档

> 版本：0.1（MVP）  
> 状态：Draft  
> 更新时间：2026-09-03

## 1. 产品概述

### 1.1 产品名称

中文名：人生内核 OS  
英文名：LifeKernelOS

### 1.2 产品定位

LifeKernelOS 是一个以个人价值观为核心、以目标和行动为载体、以状态和复盘为反馈的个人成长与生活管理系统。

它不只是记录待办事项，而是帮助用户回答并持续连接以下问题：

1. 我真正重视什么？
2. 我现在要把时间和精力投入到哪里？
3. 今天最重要的行动是什么？
4. 当前状态是否支持这样的行动？
5. 我正在变得更接近理想中的自己，还是需要调整方向？

### 1.3 产品愿景

让每个人都拥有一个可理解、可执行、可复盘、属于自己的生活系统。

## 2. 背景与问题

现有的日历、待办、笔记、习惯和情绪记录工具通常彼此割裂，用户能够积累大量信息，却难以形成从“意义”到“行动”的连续链路，常见问题包括：

- 目标很多，但无法判断当下最重要的事情。
- 计划排得很满，却忽略了精力、情绪和现实约束。
- 完成任务带来短期满足，但不一定让生活更接近长期方向。
- 复盘停留在“完成/未完成”，很难沉淀出可复用的个人规律。
- 个人数据高度敏感，用户不愿意将完整的生活轨迹交给不透明的系统。

LifeKernelOS 通过一个轻量闭环解决这些问题：定义内核，连接方向，安排行动，记录状态，定期复盘，再反向调整内核和计划。

## 3. 用户与使用场景

### 3.1 目标用户

- 希望建立长期生活系统的知识工作者、创作者和独立工作者。
- 正在经历职业、关系、城市或生活方式变化，需要重新校准方向的人。
- 使用过待办、笔记或习惯工具，但希望把碎片记录串起来的人。

### 3.2 核心场景

- 周期开始时明确近期方向和优先级。
- 每天开始时根据状态选择最重要的行动。
- 临时出现想法、承诺或任务时快速捕捉，避免打断当前节奏。
- 一天结束或一周结束时回顾事实、感受和偏差。
- 在低能量、失控或迷茫时，获得一个足够简单的下一步。

## 4. 产品目标与非目标

### 4.1 MVP 目标

- 让用户在 15 分钟内完成首次内核设置。
- 让用户每天用 3 分钟完成一次“今日启动”和一次“日终收束”。
- 让用户能看见价值观、目标、项目、行动和状态之间的关联。
- 让用户每周获得一份基于自己记录的复盘摘要，并能据此调整计划。
- 默认以隐私优先为原则，所有核心数据可导出。

### 4.2 MVP 非目标

- 不替代专业心理咨询、医疗诊断或治疗。
- 不追求复杂的社交、排行榜和公开打卡。
- 不在首版实现完整的团队项目管理。
- 不以强制连续打卡、积分和惩罚机制驱动用户。
- 不在没有用户明确授权的情况下推断或对外分享敏感信息。

## 5. 核心概念模型

| 概念 | 含义 | 示例 |
| --- | --- | --- |
| 内核 Kernel | 相对稳定的价值观、原则、边界与身份认同 | 健康、创造、诚实；不以牺牲睡眠换取短期成绩 |
| 方向 Direction | 一段时期希望靠近的状态 | 成为更稳定的独立开发者 |
| 目标 Goal | 可在周期内验证进展的结果 | 交付 LifeKernelOS MVP |
| 项目 Project | 为达成目标而组织的一组行动 | 完成产品设计、搭建应用、邀请试用 |
| 行动 Action | 下一步可在现实中完成的具体行为 | 写完首次使用流程 |
| 状态 State | 用户在当下的精力、情绪和可用时间 | 精力 2/5，可用 30 分钟 |
| 记录 Log | 对事实、想法和感受的捕捉 | 今天为什么拖延、什么让自己恢复 |
| 复盘 Review | 从一段时间的记录中提炼判断和调整 | 下周减少并行项目，保留一个主线 |

## 6. MVP 功能范围

### 6.1 首次设置：建立个人内核

用户首次进入产品时，通过渐进式问答完成基础设置：

- 选择或填写 3—5 个当前最重要的价值观。
- 记录当前阶段最想守住的边界。
- 描述未来 3—12 个月希望靠近的方向。
- 选择当前主要角色，如工作者、伴侣、父母、创作者等。
- 设置每日启动和每周复盘的提醒偏好。

要求：可跳过、可稍后补充；不以问卷分数给用户贴标签。

### 6.2 方向与目标

用户可以创建、编辑、归档方向和目标，并建立关联：

- 目标必须包含名称、周期、期望结果和当前状态。
- 目标可以关联一个或多个价值观。
- 目标下可以拆分项目，项目下可以创建行动。
- 支持“进行中、暂停、已完成、已放弃”四种状态。
- 任何目标都可以记录“为什么重要”和“什么情况下需要调整”。

验收标准：用户能够从一个目标进入其项目和下一步行动，也能反向看到该目标服务的价值观。

### 6.3 今日驾驶舱

首页展示当天真正需要关注的内容：

- 今日状态：精力、情绪、可用时间，可快速修改。
- 今日一个主线：当天最重要的一件事。
- 今日行动：按优先级显示 3—5 个行动。
- 今日承诺：用户主动选择要完成或推进的事项。
- 快速记录入口：想法、事件、情绪或临时任务。
- “我现在能做什么？”入口：根据剩余时间和精力筛选合适行动。

排序原则：先展示与当前目标和价值观关联度高、且符合当前状态的行动；不使用复杂的自动评分替代用户判断。

### 6.4 快速捕捉与记录

用户可以在任意页面快速记录：

- 一句话文本。
- 记录类型：想法、任务、事件、感受、灵感。
- 可选关联目标、项目或价值观。
- 稍后整理为行动、笔记或直接归档。

要求：打开入口后 10 秒内可以完成一条记录；记录过程中不强制填写完整字段。

### 6.5 日启动与日终收束

#### 日启动

- 我现在的精力和情绪如何？
- 今天最重要的结果是什么？
- 为了它，我要推进的第一步是什么？
- 今天明确不做什么？

#### 日终收束

- 今天实际发生了什么？
- 哪件事推进了我想要的方向？
- 哪件事消耗了我？
- 有什么需要迁移到明天或从计划中移除？
- 明天的最小可行一步是什么？

要求：默认每次不超过 5 个问题；支持一键跳过和稍后补录。

### 6.6 周复盘

系统根据用户主动完成的行动、目标进度、状态记录和文字记录生成复盘草稿，用户确认后保存：

- 本周完成与推进。
- 反复出现的阻力或干扰。
- 精力与情绪的变化趋势。
- 与价值观一致的时刻。
- 下周保留、停止、开始的事项。
- 一个下周主线和 1—3 个关键行动。

系统生成的是可编辑草稿，不把推断当作事实；用户可以删除任何不准确的结论。

### 6.7 隐私与数据管理

- 提供数据导出，首版至少支持 Markdown 和 JSON。
- 支持删除单条记录、删除某一周期数据和删除全部数据。
- 敏感记录默认不参与任何公开展示或分享。
- 明确展示数据存储、同步和 AI 能力的开关状态。
- 所有智能摘要都应标注为“基于已有记录生成的草稿”。

## 7. 关键用户流程

### 7.1 从迷茫到下一步

```text
打开今日驾驶舱
  → 记录当前精力、情绪和可用时间
  → 查看当前周期方向与目标
  → 选择一个符合状态的行动
  → 完成或记录阻力
  → 在日终收束中决定迁移、拆小或放弃
```

### 7.2 从记录到复盘

```text
快速捕捉
  → 稍后补充类型和关联
  → 在日终/周复盘中回看
  → 提炼规律与决策
  → 更新目标、行动或个人边界
```

## 8. 信息架构

- 今日：状态、主线、行动、快速捕捉。
- 方向：价值观、角色、阶段方向、周期目标。
- 行动：项目、行动清单、过滤与整理。
- 记录：日志、想法、事件、感受。
- 复盘：日终收束、周复盘、历史决策。
- 设置：提醒、数据导出、隐私、账户与外观。

底部导航首版控制在 5 个入口以内；“今日”始终作为默认落点。

## 9. 非功能需求

- 易用性：核心操作应支持键盘和移动端触控，空状态必须提供明确的下一步。
- 性能：今日首页在正常网络下应快速可用；记录提交后立即给出成功反馈。
- 可访问性：文本与控件具备清晰层级、足够对比度和键盘焦点状态。
- 可恢复性：误删前提供确认；编辑和状态变化应尽量支持撤销或恢复。
- 可解释性：任何排序、推荐和摘要都能说明依据，并允许用户关闭。

## 10. 指标与验证

### 10.1 核心指标

- 首次设置完成率。
- 首周完成至少 3 次日启动和 1 次周复盘的用户比例。
- 用户从今日页进入并完成一个行动的比例。
- 周复盘后被用户采纳或修改的决策比例。
- 30 日留存与主动记录天数。

### 10.2 质性验证问题

- 用户是否能说清楚“这个行动为什么重要”？
- 用户是否能在低能量状态下找到足够小的下一步？
- 用户是否觉得复盘带来了决策，而不只是回顾？
- 用户是否信任产品对其私人记录的处理方式？

### 10.3 反指标

- 每日填写时长持续上升。
- 未完成事项数量成为用户主要压力来源。
- 用户为了保持连续记录而填写无意义内容。
- 系统摘要被误认为诊断、评价或绝对结论。

## 11. 版本规划

### Phase 0：产品骨架

- 完成项目基础工程和数据模型。
- 完成内核、方向、目标、项目、行动、记录、复盘的最小闭环。
- 支持本地数据存储和 Markdown/JSON 导出。

### Phase 1：MVP

- 完成首次设置、今日驾驶舱、快速捕捉、日启动、日终收束和周复盘。
- 加入基础搜索、归档、提醒和隐私设置。
- 邀请少量真实用户连续使用 2—4 周。

### Phase 2：增强体验

- 日历和任务工具的可选同步。
- 基于个人历史的行动建议和阻力识别。
- 更灵活的周期、角色和模板。
- 离线优先、多端同步和更细粒度的权限控制。

## 12. 风险与应对

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 记录负担过高 | 用户觉得每天都在维护系统 | 默认极简，支持跳过、批量整理和最小可行记录 |
| 目标变成压力 | 用户被未完成清单追赶 | 强调校准和放弃的正当性，减少惩罚式反馈 |
| 智能摘要不准确 | 用户被错误结论影响 | 输出草稿、展示依据、允许编辑和关闭 |
| 数据隐私风险 | 用户不敢记录真实内容 | 透明说明、可导出、可删除、敏感内容默认私密 |
| 价值观流于口号 | 内核设置后不再被使用 | 在目标、行动和复盘中持续显示关联，但避免打扰 |

## 13. MVP 完成定义

当以下条件全部满足时，认为 MVP 达成：

- 新用户可以独立完成内核设置并创建一个周期目标。
- 用户可以从目标创建项目和下一步行动，并在今日页完成行动。
- 用户可以记录状态和文字，并在日终查看当天上下文。
- 用户可以完成周复盘，编辑并保存系统生成的复盘草稿。
- 用户可以导出和删除自己的核心数据。
- 关键流程在桌面端和移动端均可完成，且不存在无法退出或无法恢复的死路。
