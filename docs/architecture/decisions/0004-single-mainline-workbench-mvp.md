# ADR-0004：MVP 以单一主线工作台为中心

> 分类：Architecture Decision Record
> 状态：Superseded
> 日期：2026-09-05
> 影响范围：产品入口、主线与任务模型、导航和后续 AI 边界
> 替代决策：`ADR-0006` 多个长期目标与单一当前行动

## 背景

> 历史说明：本 ADR 记录现有“单一主线”原型的形成过程。2026-09-06 起，产品方向由 [ADR-0006](0006-multiple-long-term-goals-and-single-current-action.md) 替代；本文件不再作为后续功能设计依据。

LifeKernelOS 的价值不在于提供另一套短期待办，也不在于要求用户先填写精力、可用时间或复杂的目标体系。用户需要的是维护一件长期重要的事，并清楚看见自己是否在推进它。

原有按状态选择行动的方案会让首次使用多出多个决策，也会把页面的注意力从长期主线移到当日筛选。它不再符合当前的 MVP 假设。

## 决策

- MVP 只保留两个用户入口：首页和工作台。
- 首页解释产品的用途和三步方法：写下主线、加入下一步、手动确认进度。
- 工作台使用左侧最小导航和右侧主内容区；用户首次只输入一条当前主线名称。
- 每个账号同时只维护一条 active Focus。Focus 的进度由用户手动确认，范围为 `0—100`；进度达到 `100` 时才完成主线。
- 任务只需名称和完成状态，且必须属于当前主线。完成任务不会自动改变主线进度。
- 首版不收集精力、可用时间、预计时长、今日选择或优先级，也不提供明暗主题切换。
- `SPEC-0002` 的状态匹配与候选选择方案被替代，不进入实现。
- Agent 能力放在主线闭环验证之后：它只能提出任务拆解或说明任务与主线的关系、必要性；任何创建、删除或进度修改都必须由用户确认。

## 后果

- 首次进入的路径缩短为“输入一件长期想推进的事”，更容易理解和开始。
- 产品需要清楚区分任务完成和主线完成；进度的判断权保留给用户。
- 暂时失去按当日状态筛选行动的便利，但避免用复杂输入替代真正的推进。
- 日终收束、捕捉、复盘和 Agent 都需要在核心闭环得到真实使用验证后，重新确认必要性和边界。
