# ADR-0005：我的画像以目标与行动事实为依据

> 分类：Architecture Decision Record
> 状态：Accepted
> 日期：2026-09-05
> 影响范围：目标完成记录、个人画像、数据导出与后续 Agent 边界

> 更新说明（2026-09-06）：画像已由 [ADR-0007](0007-two-tab-console-information-architecture.md) 确认为第二个一级 Tab；事实与用户确认原则保持不变，界面术语使用主线与 To-do。

## 背景

LifeKernelOS 不应只在用户推进目标时发挥作用。目标、行动结果和用户亲自确认的总结，也应成为用户回看自身经历的依据。

但“画像”很容易越界成系统替用户定义人格、能力或心理状态。这既不可验证，也违背用户拥有自己人生叙述权的原则。

## 决策

- “我的画像”是工作台左侧第二个一级 Tab，承接目标、行动、经历与知识的长期沉淀。
- 画像的事实来源仅限于当前用户的 Goal、Action、GoalReflection、ProfileDescription 与用户主动关联的 KnowledgeItem。
- 页面显示由数据直接计算的中性概览和关系图谱；每个目标或知识节点必须可追溯到原始记录。
- 用户可为一条已完成目标留下经历总结，也可编辑一段整体“我的描述”。这些文字不改变原始 Goal 或 Action。
- 知识状态由用户确认，不能由系统自动判定。
- 没有目标时展示解释性空状态，不强制用户提前填写自我介绍。
- 不引入性格标签、能力评级、心理推断、成就排名或自动化 AI 文案。
- 将来如引入 Agent，它只能基于用户明确选择的经历和可见事实草拟文本，必须展示依据并经用户确认后保存。

## 后果

- 产品从“推进目标”延伸为“理解目标与行动留下的经历”，但仍以用户真实记录为事实来源。
- 需要保留目标和行动完整记录，并增加经历总结、整体描述、知识沉淀及其导出边界。
- 画像的第一版可能比较朴素；这是有意的，避免漂亮但无法解释的人格叙述。
- `SPEC-0011` 依赖目标、行动、服务端身份和数据导出能力，不能跳过事实层单独生成画像。
