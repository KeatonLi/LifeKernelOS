# ADR-0006：多个长期目标与单一当前行动

> 分类：Architecture Decision Record
> 状态：Superseded
> 日期：2026-09-06
> 影响范围：产品定位、目标与行动模型、导航、推荐逻辑和后续 Agent 边界
> 替代：`ADR-0004` 的“单一主线工作台”产品决策；现由 [ADR-0008](0008-mainline-groups-derived-todo-progress.md) 替代

## 背景

用户的人生中通常同时存在多个长期目标，例如工作成长、个人项目、健康和家庭事项。强制用户把其中一项声明为唯一“主线”，会把其他真实责任误解为支线，也会让优先级变化变成产品内的失败或锁定。

LifeKernelOS 真正需要收束的不是长期目标数量，而是用户在一个具体时刻要执行的行动数量。用户可以拥有多个长期目标，但在时间和精力有限时，仍需要明确“现在做什么”。

现有“单一主线 + 任务列表 + 手动百分比”模型主要保存用户已经做出的决定，不能充分验证“帮助用户找到下一步”的价值假设。手动百分比又缺少统一完成基准，容易制造虚假精确度和额外维护负担。

## 决策

- 产品统一使用“长期目标”概念，不再把长期目标称为“主线”。
- 每个用户可以同时维护多条 active 长期目标，不设置“唯一当前目标”。
- 聚焦约束移动到行动层：每个用户全局同时最多有一个当前行动。
- 每条行动必须关联一个长期目标；临时捕捉在完成归属前不参与当前行动推荐。
- 用户可以记录当前可用时间和精力，系统据此缩小候选范围并说明理由；用户始终可以查看全部行动和手动覆盖。
- 行动必须支持完成、拆小、卡住和放弃，以上结果都被视为有效处理。
- 长期目标由用户明确完成、暂停、恢复或放弃，不根据行动数量自动推断状态。
- 新目标不使用 `0%—100%` 手动进度；可选的完成定义和行动事实承担进展解释。
- “我的画像”作为第二个一级 Tab，使用目标和行动事实形成可追溯图谱；它不替用户推断人格、能力或目标价值。
- Agent 只能提出候选、拆解和理由，不替用户自动创建、切换、完成或删除目标与行动。

## 后果

- 产品不再要求用户把复杂人生压缩成一条唯一主线，更符合多目标并行的现实。
- 产品差异化从“更少的目标管理”转向“从多个长期目标中找到现在的一步”。
- 数据模型需要从 Focus 的单 active 约束迁移到 Goal 多 active 模型，并增加全局唯一当前行动约束。
- 原“现在 / 长期目标 / 画像”三入口不能继续代表当前产品，需要按 ADR-0007 合并为两个一级 Tab。
- 状态输入和行动属性会增加少量记录成本，因此必须允许缺省、提供少量离散选项，并通过真实试用验证其收益是否大于负担。

## 实施边界

- 本 ADR 确认产品方向，不直接授权修改数据库或现有用户数据。
- `SPEC-0010` 进入 `Accepted` 且迁移设计完成前，现有实现仅作为可运行基线，不宣称符合新 PRD。
- 迁移必须保留现有 Focus、Action、经历总结、画像描述和知识沉淀数据，并保持可导出。
