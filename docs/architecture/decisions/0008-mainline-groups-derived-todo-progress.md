# ADR-0008：主线分组与派生 To-do 进度

> 分类：Architecture Decision Record
> 状态：Accepted
> 日期：2026-09-06
> 影响范围：产品术语、`SPEC-0010`、`SPEC-0011`、Action 数据、Profile DTO、导出与前端双 Tab
> 替代关系：替代 [ADR-0006](0006-multiple-long-term-goals-and-single-current-action.md)

## 背景

现有多 Goal + 当前 Action 模型保留了正确的“多个方向、一个当前行动”约束，但界面和术语没有让用户直观看出 Goal 是 To-do 分组，Action 也缺少独立内容。旧决策同时排除了任何百分比，导致用户完成 To-do 后看不到清楚、可信的推进反馈。

用户确认产品应以“主线”作为 Goal 的可见名称：每条主线包含多个 To-do；To-do 完成应自动推导主线进度；进度还应成为画像图谱中的事实。

## 决策

- 领域模型继续使用 `Goal` 与 `Action`，用户界面将 `Goal` 称为“主线”，将 `Action` 称为“To-do”。
- 用户可同时拥有多条主线，不存在唯一主线；全局唯一约束仍只作用于当前 To-do。
- Action 增加可选 `content` 字段，用于保存 To-do 的详细内容；标题、内容、元数据和处理结果均归属该 To-do。
- 主线进度为服务端派生投影，不允许手动编辑或持久化为新的权威百分比。
- 有效 To-do 为 `available`、`completed`、`blocked`；派生进度为 `round(completed / effectiveTotal × 100)`。没有有效 To-do 时为 `0%`。
- 主线明确完成时投影为 `100%`，但不会自动完成主线或改写未完成 To-do。
- 主线进度同时进入主线任务板、ProfileView 与 Goal 图谱节点；图谱不为每条 To-do 创建节点。
- 控制台仍只保留“主线”和“我的画像”两个一级 Tab，设置继续位于侧栏底部。

## 备选方案

### 方案 A：每完成一条 To-do 固定加 1%

- 优点：规则表面上很直观。
- 代价：3 条 To-do 的主线完成后只有 3%，必须在最后一步跳到 100%，无法反映实际推进。
- 未选择原因：会制造不可信的反馈，且与“按任务分组推进”的心智模型不一致。

### 方案 B：继续完全不展示百分比

- 优点：不需要新的投影和 DTO。
- 代价：用户无法快速感知 To-do 完成带来的主线变化，画像图谱也缺失关键事实。
- 未选择原因：不能满足本次已确认的可见推进需求。

## 后果

### 正向影响

- 主线、To-do、当前行动和画像图谱形成一个统一且易解释的模型。
- 进度始终可由原始 To-do 状态重新计算，不存在手填漂移。
- 画像可以展示真实积累，而不跨越到人格或能力推断。

### 代价与风险

- 需要 Action 内容字段、数据库迁移、DTO 和导出版本升级。
- 新增或移除有效 To-do 会导致派生百分比重算；前端必须明确显示“完成数 / 总数”，避免只呈现百分比造成误解。
- 主线明确完成但仍有未完成 To-do 时显示 100%，属于用户主动确认的结果，界面需保留状态提示。

## 实施边界

- 必须同步 PRD、`SPEC-0010`、`SPEC-0011`、`SPEC-0007`、系统架构、详细技术设计、API 类型、迁移与测试。
- 物理表名继续保留历史 `focuses` / `actions`；进度不复用旧 `focuses.progress_percent` 的手填语义。
- 不引入目标层级、自动推荐人格判断、To-do 图谱节点或第三个产品 Tab。

## 验证方式

- 自动化测试覆盖内容迁移、内容更新、有效 To-do 分母、四舍五入、主线完成 100% 和 Profile 用户隔离。
- 浏览器验收覆盖桌面与移动端主线任务板、当前 To-do 完成、进度更新、图谱交互和事实回退。
