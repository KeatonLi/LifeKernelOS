# Architecture 文档

Architecture 文档是 LifeKernelOS 系统边界和长期技术选择的事实源，回答“产品如何可靠地成立”。

## 本目录负责

- 系统上下文、模块边界和依赖方向。
- 服务端、前端、数据库、认证和部署边界。
- 数据模型、API DTO、事务、迁移和安全约束。
- 影响多个 Spec、需要长期遵守的产品或技术决策。

单个功能的完整行为和验收场景属于 [Specs](../specs/README.md)，产品价值与范围属于 [Product](../product/README.md)。

## 什么时候需要 ADR

满足任一条件时，先新增或更新 ADR：

- 选择影响两个或更多 Spec；
- 改变产品一级信息架构或核心领域模型；
- 改变数据事实源、部署形态、认证或安全边界；
- 存在多个合理方案，未来 Agent 需要知道为什么选择当前方案；
- 将替代一个已接受的长期决策。

局部实现细节、可逆的组件选择和单个 Bug 修复通常不需要 ADR。新 ADR 使用 [决策模板](decisions/TEMPLATE.md)。

## AI 读取与更新规则

1. 先读本入口，判断要读系统架构、详细技术设计还是某项 ADR。
2. 再读相关 Spec，避免让技术方案改变已经接受的用户行为。
3. 发生长期选择时先写决策和后果，再改设计与代码。
4. ADR 一经替代，保留原文并标为 `Superseded`，同时链接替代它的新 ADR。
5. 架构文档描述当前系统；不要把未经接受的未来方案混进当前基线。
