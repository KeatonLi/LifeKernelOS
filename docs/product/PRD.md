# LifeKernelOS 产品需求文档

> 版本：0.7
> 状态：Accepted
> 更新时间：2026-09-06
> 文档域：Product
> 核心变更：以“主线分组 → To-do → 可追溯画像图谱”收束产品模型，并引入由 To-do 自动推导的主线进度。
> 产品决策：[ADR-0007 双 Tab 控制台信息架构](../architecture/decisions/0007-two-tab-console-information-architecture.md)、[ADR-0008 主线分组与派生 To-do 进度](../architecture/decisions/0008-mainline-groups-derived-todo-progress.md)

## 1. 产品是什么

LifeKernelOS 是一个帮助用户推进主线、看见积累的个人系统。它只做两件事：

1. 让用户把一条主线拆成清楚的 To-do，并在此刻只做一件事。
2. 将主线、完成的 To-do 和知识沉淀汇聚成可追溯的“我的画像”图谱。

```text
主线分组
  └── To-do（标题、内容、状态）
        └── 当前只做一个
                 ↓
        完成事实与知识沉淀 → 我的画像图谱
```

产品不是人格测试、项目管理套件，也不替用户判断哪条主线更重要。一个用户可以并行维护多个主线；“聚焦”只发生在当前 To-do 层。

## 2. 目标用户与核心处境

产品服务同时推进工作、学习、健康或个人项目的个人用户。他知道想走向哪里，却容易被一长串待办淹没；完成过的事情和形成的知识也常散落在不同地方，难以看见长期积累。

LifeKernelOS 要让他一眼知道：**我现在做什么、它属于哪条主线、做完后我推进了多少。**

## 3. 产品假设

### 3.1 推进假设

如果主线天然表现为包含 To-do 的分组，用户只需打开一个清楚的任务板就能看到当前 To-do、其详细内容和真实进度，那么他更容易开始并持续推进。

### 3.2 画像假设

如果产品将主线的完成比例、To-do 完成事实和知识关系放入一张可交互的图谱，而不越权做人格或能力判断，用户就能更可靠地理解自己正在形成的方向。

## 4. 产品原则

1. **主线可以有多个，当前 To-do 只能有一个。** 任何主线都不天然是“唯一主线”或次要支线。
2. **主线是分组，To-do 是可执行内容。** 每个 To-do 都必须归属一条主线，并拥有标题、可选详细内容和处理状态。
3. **进度来自完成事实，不靠手填。** 用户不能编辑百分比；系统按有效 To-do 中已完成的比例计算，主线明确完成时显示 `100%`。
4. **一个屏幕先回答一件事。** 主线页的首要信息是当前 To-do；画像页的首要信息是图谱。其他维护能力不能挤占核心视线。
5. **画像来自事实，也归用户所有。** 图谱只连接可追溯的主线、To-do、知识和用户确认文字，不推断人格、能力、价值观或心理状态。
6. **调整也是有效结果。** 完成、拆小、卡住和放弃都能结束一次 To-do 处理，不用假完成掩盖现实。

## 5. 控制台信息架构

左侧只保留两个一级 Tab，设置作为底部齿轮辅助入口：

1. **主线**：主线分组、To-do、当前行动与推进进度。
2. **我的画像**：以用户为中心的主线—知识关系图谱与可追溯事实。

### 5.1 主线

主线页是一个不需要在多个区域来回滚动的任务板：

- 顶部清楚展示当前主线名称、完成数量和细进度条；
- 左侧是该主线的 To-do 顺序列表；
- 右侧是选中 To-do 的详细内容、完成标准和下一步操作；
- 当前 To-do 使用明确的视觉强调与一个主按钮；
- 用户可以切换或新建主线，并在需要时增加、编辑或调整 To-do。

状态匹配、时间和精力仍然可用，但属于“帮我选择”的辅助能力；它不应压过任务板或成为首次使用的门槛。

### 5.2 我的画像

我的画像以图谱为主画面：

- 中心是“我”；
- 每条主线是一个可点击节点，显示名称、`已完成 / 有效 To-do 总数` 和派生百分比；
- 知识节点连接到来源主线；
- 图谱支持缩放、平移和一键适配视图；
- 图谱下方保留“关于我”、当前 To-do 和知识事实入口，保证图谱之外也能读到等价事实。

## 6. 功能范围

### 6.1 主线与 To-do

- 用户可以创建、编辑、暂停、恢复、完成、放弃和重新打开多条主线。
- 每条 active 主线可以创建、编辑和查看多个 To-do。
- To-do 包含必填标题、可选详细内容、可选预计时长与精力要求，以及可追溯的处理结果。
- 用户从任意 active 主线中确认全局唯一的当前 To-do。
- 当前 To-do 支持完成、拆小、卡住、放弃和释放选择。

### 6.2 派生进度

- 有效 To-do 指状态为 `available`、`completed` 或 `blocked` 的 To-do；`abandoned` 与 `superseded` 不进入当前进度分母。
- active 或 paused 主线的进度为：`已完成有效 To-do 数 / 有效 To-do 总数 × 100`，四舍五入为整数；没有有效 To-do 时为 `0%`。
- 主线状态为 completed 时显示 `100%`，但系统不根据 To-do 数量自动把主线标为完成。
- 新增、完成、卡住、放弃或拆小 To-do 后，进度在下一次读取时即时重算。

### 6.3 我的画像

- 图谱实时汇聚当前用户的主线、进度、完成 To-do 数和知识关系。
- 用户可以维护自我描述、完成主线的经历总结和知识内容；这些文字不反向修改主线或 To-do 的事实。
- 图谱不展示每个 To-do 节点，避免视觉噪声；To-do 完成度聚合在主线节点上。

## 7. 核心验收

- 用户打开主线页后，不滚动即可理解当前主线、当前 To-do、其内容和进度。
- 用户完成一个当前 To-do 后，所属主线的完成数量和派生进度更新，且当前选择被释放。
- 用户能从一条主线切换到另一条主线，并始终只保留一个当前 To-do。
- 用户打开我的画像后，可看到自己、主线、知识及每条主线的完成比例关系，并能追溯至原始记录。
- 刷新或跨设备登录后，主线、To-do 内容、状态、当前选择和画像事实保持一致。

## 8. 数据与安全边界

- 服务端是主线、To-do、进度和画像事实的唯一数据源；前端不直接读写数据库。
- 进度为服务端读取时推导的事实，不持久化为可编辑百分比。
- 所有记录按当前用户隔离；用户正文不发送给第三方分析或 AI 服务。
- 用户可以导出主线、To-do、当前状态、画像事实和状态历史；导出不包含密码或 Session。

## 9. 本版不做什么

- 不自动判断哪条主线最重要，也不替用户创建、切换、完成或删除 To-do。
- 不做主线层级树、OKR、团队协作、排期、日历同步、提醒、打卡、排行榜或公开画像。
- 不做人格、能力、价值观、心理状态或职业适配推断。
- 不将每条 To-do 直接绘制为画像图谱节点。

## 10. 首轮验证指标

- 至少 5 名拥有两个以上主线的真实用户完成 7 天试用。
- 已有 To-do 时，从打开主线页到确认或完成当前 To-do 的中位耗时不超过 60 秒。
- 至少 70% 的当前 To-do 以完成、拆小、卡住或放弃之一得到明确处理。
- 至少 3 名用户能从图谱准确指出一项主线—知识或主线—经历联系。
- 访谈中，“看不懂页面该做什么”或“记录比行动更累”不能成为主要负面反馈。

## 11. 规格与交付状态

- `SPEC-0010`：主线分组、To-do 内容、派生进度与唯一当前 To-do。
- `SPEC-0011`：我的画像的进度感知图谱与事实层。
- `SPEC-0007`：数据导出契约随 Action 内容字段升级。
- 三个规格在代码和自动化测试完成后才可标记 `Implemented`；逐条人工验收通过后才可标记 `Verified`。
