# LifeKernelOS PRD v0.12：行动积累与个人成长卡片

> 版本：0.12 评审稿

## 1. 一句话定义与评审摘要

**一个把每天完成的 Todo，变成目标积累和个人成长卡片的小工具。**

用户不必额外写成长日记：做过的事情本身就是素材。AI 帮他看见“我在往哪里走、最近推进了什么、正在形成怎样的行动特点”；成长值、等级和里程碑让这种积累可见。

核心体验示例：用户完成“剪完并发布第一条视频”，系统立即保存完成，随后自动归入“自媒体”，显示“创作成长值 +10”。画像卡片增加这条有日期的记录，积累达到门槛时升级。AI 分析会引用这条任务说明“本周从准备转向了实际发布”，用户能点回原任务核对。

本文的核心方向来自用户，以下细则是本次建议，需要审核后才生效：

| 议题 | 评审稿建议 |
| --- | --- |
| 目标数量 | 最多四个同时启用的成长目标，名称可自定义，允许槽位留空；“自媒体、理财、健身”只是示例 |
| 自动归属 | 每个完成任务只归一个主要成长目标；用户明确指定优先，AI 只补没有明确归属的任务 |
| 自动分析 | 完成后自动打标；事实和成长值即时更新；有新事实且当日尚未自动分析时，打开画像自动生成一次推进分析和最近七日总结 |
| 成长反馈 | 建议有效完成任务每条 +10，100 成长值升一级；重复勾选、换标签不重复加分，原任务与子任务不双重计分 |
| 画像表达 | 形成有依据、可修改的行动画像；用户完成的记录、AI 解读和用户自述分开展示 |
| AI 联网 | 用户一次开启自动功能并确认发送范围后按规则触发，默认关闭；不要求每个任务再次确认 |

## 2. 用户问题与产品价值

同时推进几个生活方向的人往往有两个问题：待办越来越长，完成之后却看不见积累；忙了一周，仍难以说明哪些事情真的推进了自己的目标。

产品要连续回答四个问题：

1. 我今天完成了什么？
2. 它为哪个长期方向留下了积累？
3. 最近我在哪些方向有行动、哪些方向暂时没有记录？
4. 从这些行动中，我能看到怎样的自己，接下来可以怎么走？

希望用户感受到“这一步没有白做，我的角色在成长”。增长的是已记录行动的积累，不把任务条数等同于健康、财富、收入或实际能力。

## 3. 概念与现有产品的关系

| 概念 | 产品含义 | 边界 |
| --- | --- | --- |
| 成长目标 | 用户想持续投入的生活方向，如创作、财务管理、健身、学习 | 长期方向，不是必须达到 100% 的一次性项目 |
| 主线 | 当前已经存在的任务分组或项目 | 保留原任务组织；多条主线可以关联同一个成长目标 |
| Todo | 一件可执行、可记录完成的事 | 创建、完成和离线保存不依赖 AI |
| 目标归属标签 | 完成任务与一个成长目标的关系 | 记录 AI / 用户来源；可以纠正；不改任务原主线 |
| 成长值 / 等级 | 有效完成记录的游戏化反馈 | 不表示实际能力分数，也不是现有任务完成百分比 |
| 个人成长卡片 | 目标卡片、完成依据、行动特点与阶段总结 | AI 解读单独标识，不改写任务事实或用户自述 |

本稿建议在现有主线之上增加轻量的“成长目标”归集维度，而不是把所有已有主线强行压缩为四条。用户只使用一个 Todo 列表和同一批任务，不维护第二套任务。

首次使用可先设置一个方向、完成一个任务，四个槽位无需全部填写。没有主线的快速任务进入明确的“未分组”任务区域；快速记下仍是收集入口，转换成 Todo 后才参与完成与成长。新建任务不要求先完成分类。

已有数据保留全部主线、任务、知识、日期和关系。升级后由用户选择成长目标与主线关联；历史任务不默认批量联网分类，不丢弃第四个之外的旧主线。历史补标需单独展示数量、范围并由用户发起。

成长目标可以改名或归档，归档后释放启用槽位，历史记录与来源仍可访问。改名不等于更换人生方向：目标定义发生实质变化时保留历史定义，用户决定新建目标或明确迁移归属，系统不把旧创作记录悄悄变成理财积累。新任务不能自动归入已归档目标。

## 4. 完整用户旅程

| 时刻 | 用户行为 | 产品响应 |
| --- | --- | --- |
| 建立方向 | 命名一至四个成长目标，填写可选的一句话定义 | 显示目标卡片；不预填任务或生成虚假的成长数据 |
| 日常行动 | 快速录入任务，可选主线、目标和日期 | 保留简约 Todo 体验；不强制维护分类 |
| 完成 | 勾选任务 | 本地先保存，显示完成和个人成长值；已知归属时同步更新对应目标 |
| 自动归集 | 无需新增操作 | 已启用 AI 时后台识别未明确归属的任务，成功后归入目标；不确定则保留“待确认” |
| 即时反馈 | 看见目标成长变化，或达到里程碑 | 轻量反馈和可关闭的升级动效；任务列表操作不中断 |
| 回看 | 打开我的画像 | 先看到四个目标的积累、个人卡片与可追溯记录；满足触发条件时自动生成分析 |
| 调整 | 改正分类，撤销完成或调整方向 | 事实与成长值一致修正，旧分析标记待更新；不伪造新完成 |

主界面仍保留“主线”和“我的画像”两个一级入口，暂不改名。成长目标是主线页的轻量概览与筛选，不新增导航层级；我的画像升级为卡片主画面，既有图谱作为可切换的关系视图保留，知识与自述入口继续可访问。

## 5. 完成后的 AI 自动打标

### 5.1 归属规则

- 优先级：用户对该任务的明确归属决定（包括“其他”）> 用户明确设置的主线默认成长目标 > AI 识别 > 未归类。选择“其他”后 AI 不反复要求归类。主线关联修改不追溯覆盖已有人工任务标签；批量改动必须另行确认。归档目标不再作为新归属的主线默认值，历史已完成标签保留。
- AI 根据任务标题、允许发送的内容以及已启用目标的名称和定义，返回一个目标、简短理由，或“无法判断 / 不属于这些目标”。不能创建第五个目标或把一条任务强行归类。
- 明确结果自动应用并显示“AI 归类”；歧义结果只显示候选和“待确认”，不凭模型自报置信度声称准确率。用户可以选择另一个目标或“其他”，也可继续行动而不处理候选。
- 每条完成任务首版只有一个主要目标，不向多个目标重复分配成长值。额外技能标签、标签树与多目标权重不进入首版。
- 人工纠正立即成为事实，原 AI 理由保留为可追溯记录；后续 AI 不能覆盖该人工决定。

### 5.2 异步与恢复

任务完成不等待网络。无 Key、未开启自动功能、离线、限流或模型错误时，任务仍完成并获得个人成长反馈；用户可以手动归属。未归属任务不增加任一目标的成长值。

同一个完成版本只创建一项打标工作，多窗口、重复点击和程序重启不重复发起。晚到结果遇到撤销完成、编辑、人工改标、目标定义变更或数据导入时失效，不能覆盖新事实。

离线任务进入可见的待处理队列；应用运行、开启状态有效且网络恢复后按预算续处理。服务失败不无限自动重试，保留原因和明确重试入口；关闭自动功能会停止队列并取消在途请求，晚到结果失效。取消完成操作使其打标工作失效。

编辑已完成任务的标题或用于归类的内容后，个人完成贡献保持不变；AI 来源的归属失效，目标贡献暂时转入未归类，并按最新快照建立一项新归类工作，仍受每日预算限制。用户明确指定或已生效的主线默认归属保留，用户可主动调整；新的有效归属只转移目标值，不新增个人值。旧分析相应标记待更新。

## 6. 目标归集与个人成长卡片

每个目标卡片展示目标名称、成长值与等级、累计有效完成数、最近七个本地日期内的完成数、最近一次行动日期，以及可展开的完成任务列表。每条记录能查看原任务、完成日期、归属来源和修改入口。

个人成长卡片包括：

1. **行动事实**：累计有效完成数、最近七日记录、目标分布和已达到的里程碑。
2. **近期的我**：AI 根据选定期间提出的行动特点，例如“近期持续投入创作与训练”；附具体任务依据和时间范围。
3. **阶段总结**：做过什么、哪些方向有积累、哪些方向没有记录，以及一至三条可选下一步建议。
4. **我的表达**：用户自己保留或修改的自述，与 AI 文案分开保存。

“没有记录”只表示此工具中未记录，不能写成“你不重视健身”。AI 可以说“记录显示你本周持续进行创作”，不能断言“你天生自律”“你投资能力很强”。本版以行动画像回答“我正在成为怎样的人”；长期人格、心理诊断与专业能力评级不在范围内。

用户可以隐藏 AI 行动特点、修改表达或另存为自己的卡片文案。修改不覆盖来源事实；下一次 AI 生成不覆盖用户文字。空状态只解释如何积累，第一条记录后即可展示真实卡片，不要求达到等级才开放画像。

## 7. 自动推进分析与个人总结

### 7.1 触发和范围

- 事实计数、目标成长值和等级由本地记录即时更新，不调用 AI。
- 自动分析开启后，打开“我的画像”时，若存在自上次成功分析以来的新完成、撤销、归属纠正、已完成任务内容修改或目标定义变化，且本地当天尚未自动发起分析，自动发起一批。早上没有新事实，下午完成任务后再次打开仍可触发当天第一次分析。没有新事实不发请求；无有效完成依据不生成画像结论。
- 一次生成各目标的推进分析与个人总结，默认覆盖最近七个本地日期（含今天），明确起止日期。一天至多一次自动分析；用户可主动重新生成，另行提示费用。
- 期间计数按当前有效完成任务去重，并使用其最新有效完成的本地日期；事件与被撤销记录用于解释历史，不叠加到本期完成数。迁移数据完成日期未知时只计累计事实，不计入七日统计。
- 某目标没有完成记录时使用事实空状态，不让模型编造推进。待归类任务计入个人完成事实，并明确列出未归类数量，不能当成任一目标的推进。
- 历史总结保存生成时间、期间和事实依据。事实变化时显示“依据已变化，待更新”，当天不连续自动计费，用户可主动更新；晚到结果不成为当前分析。
- 离线等导致尚未发出请求时不消耗机会，恢复后下一次满足条件的打开可以触发。已发出请求的失败会消耗当天自动机会，反复打开不自动重试；保留错误与用户主动重试入口，次日仍有未分析的新事实时可使用新的每日机会。

### 7.2 输出契约

| 输出 | 必须包含 | 不得声称 |
| --- | --- | --- |
| 目标推进分析 | 本期已记录行动、引用任务、与用户目标定义的关系、一条可选下一步 | 凭 Todo 数量推定真实收入、收益、体脂变化或人生目标完成百分比 |
| 个人总结 | 日期范围、行动分布、可观察的变化、依据不足的说明 | 工具没记录的生活事实、长期人格定论或心理状态 |
| 成长卡片文案 | 简短行动特点、对应依据、AI 生成标识、编辑与隐藏入口 | 将模型评价当作确定事实或自动覆盖用户自述 |

分析使用有效完成事实和可选的用户目标定义。首版只分析本期，不输出“比上周提高”等跨期增减；后续跨期比较必须使用可复核的事件与当时快照，无基线不比较。下一步建议只是建议，不自动新增、排期、修改或完成任务。

## 8. 游戏化反馈的第一版

以下数值是评审建议，尚未接受。首版采用可解释的简单规则：

- 一个当前有效完成的 Todo 为个人贡献 10 成长值，重复完成同一有效记录不叠加；归属明确后向其主要目标贡献同样 10 值。
- 个人成长值 = 全部有效完成任务数 × 10；目标成长值 = 该目标有效完成任务数 × 10。未归类任务使目标值之和小于个人值，界面解释这一差额；多目标不重复计分。
- 个人与目标的 +10 是同一完成在两种视角中的呈现，不是总计 +20。个人值包含归档目标与其他 / 未归类记录；四个启用目标卡片的值之和可能更小，归档记录有单独入口。
- 等级 = 1 + 成长值整除 100；零成长值是初始 Lv.1。显示到下一等级还差多少，以及每次增长的原任务依据。
- 建议里程碑：首次完成、某目标累计完成 10 / 25 / 50 条。领取以有效事实为准，每个里程碑只展示一次新达成反馈；重新达到时不重复奖励。
- 撤销完成、移除完成事实或恢复为未完成时撤回对应个人 / 目标成长值。改目标只转移目标值，不增加个人值；重新完成恢复同一任务的贡献，不重复累计。
- 拆解后的原任务不作为完成计分。曾完成的任务需先撤销才可拆解；有效完成的子任务按各自记录计分，并保留来源链。界面说明成长值计量已记录的小步，不公平比较任务难度。
- 首版不能彻底阻止人为把任务写得更碎来增加条数；这是简单计分方案的已知局限，试用中单独观察，不宣称已解决所有刷分问题。
- 成长目标归档保留历史记录和成长值；重新启用不重新奖励。第一版展示当前有效等级，事实撤回时允许回落，明确解释原因而不播放惩罚反馈。

反馈采用“完成 → 归集 → 小幅增长 → 达标升级”的短节奏，不要求看完动画才能继续。可关闭动效并遵循减少动态效果设置。没有连续签到惩罚、等级清零、随机奖励、榜单或跨人比较。

原有主线的“任务完成 2/6”继续表达当前任务集合的完成比例；长期成长目标只显示积累，不显示“人生目标完成 33%”。真实里程碑，例如发布十条视频，必须由用户明确记录结果或确认，不能仅凭任务数量推定。

## 9. 数据、AI 费用与使用控制

AI 自动化开启页解释提供商、发送内容、触发规则和可能产生的费用。打标与分析提供独立开关；用户开启后系统按约定自动处理，不每次弹确认，也不因保存 Key 而自动开启。

| 场景 | 默认发送范围 | 控制 |
| --- | --- | --- |
| 单任务归类 | 该任务标题、四个目标的名称 / 定义 | 详细内容默认不发，可单独允许；不发知识库、自述或其他未完成任务 |
| 推进分析 | 期间、各目标完成计数、归属和本期完成任务标题 / 日期 | 最多携带最近 50 条完成依据，超出时给本地汇总并标识正文依据不完整；详细内容默认不发 |

正文会被发送到用户配置的模型服务，因此本地保存不能表述为“任何数据都不离开设备”。沿用当前 BYOK 和系统密钥存储，Key 不进入任务、画像、备份、提示词或日志。

建议默认每日最多 20 次自动打标请求与一批自动分析，失败请求也计入上限；未发出的工作留在队列，次日应用运行且开启状态有效时续处理。用户可暂停、降低或明确调整上限。费用按用户服务商实际计费，本应用不以请求条数声称精确金额。显示待处理数量、自动请求次数及失败情况，不无限重试或后台重生成历史。

发送上限导致某目标没有具体任务正文依据时，该目标只展示本地计数和依据不足提示，不生成针对具体行为的解读。明确要求模型将任务文本当作数据，输出须校验允许的目标与引用；生成内容不执行命令、不渲染任意 HTML、不获得本机工具权限。

完成、撤销、恢复、归属纠正与成长投影必须有同一事实源和重复操作保护。保存可追溯的完成事件、撤销关系、任务 / 目标快照、AI 来源和分析版本；导入后旧网络结果失效。旧备份不能补造不存在的历史：只能迁入仍可验证的完成事实，未知历史时间单独标识，不用于按周比较。

新的成长目标、人工归属、事件、卡片、里程碑和分析记录需要进入新版备份，版本号、迁移及恢复验收在后续 Spec 定义。自动联网开关与 Key 不随导入自动启用；恢复数据之后不重播升级反馈、不默认批量发送历史任务。

## 10. 第一版范围和明确不做

| 首版必须形成闭环 | 以后按反馈扩展 |
| --- | --- |
| 四个可自定义成长目标，未分组 Todo 与已有主线兼容 | 多目标权重、技能树、复杂任务难度分数 |
| 完成后自动归类、待确认与人工纠正、失败恢复 | 画像分享、角色皮肤、长期称号系统 |
| 目标完成归集、个人卡片、简单成长值与里程碑 | 真实结果指标与个性化成就模板 |
| 自动目标推进分析与最近七日个人总结，可追溯和可隐藏 | 更长周期的复盘、趋势与跨期对比 |
| 撤销 / 重复操作 / 多窗口 / 备份恢复一致 | 云同步、移动端、社交与团队能力 |

现有 AI 任务拆解继续保留原“主动生成、预览、明确应用”的契约。自动打标只维护成长归属，不替用户改变主线或任务内容；自动分析不取得任务执行权限。帮助开始、处理卡住与日终 / 周复盘独立保存流程不因本稿自动进入首版。

## 11. 产品验收场景

| 场景 | 应得到的结果 |
| --- | --- |
| 完成首条“发布视频”任务 | 完成立即保存；已启用 AI 时后台归类，个人与对应目标各 +10；卡片可追溯原任务 |
| 无 Key 或断网完成任务 | Todo 不受阻；个人积累可见；允许手动归属，失败不伪造 AI 结果 |
| 完成歧义或生活杂务任务 | 可待确认或归为其他；不被强行计入四个方向 |
| 已人工指定目标，AI 晚到 | 保留人工目标，不重复奖励、不移动原主线 |
| 双窗口重复完成、重启重放 | 一个有效完成贡献一份成长值；一个完成版本不重复创建模型工作 |
| 先完成再撤销，网络结果稍后返回 | 贡献撤回、归类工作失效；旧结果不能恢复完成或更新当前分析 |
| 将已完成任务从创作改到健身 | 两目标值同步转移，个人总值不变，分析标记待更新 |
| 编辑已有 AI 归属的完成任务 | 个人值不变，原目标贡献转待归类；新快照归类后只转移目标值，旧结果失效 |
| 打开画像且有新完成 | 当日尚未自动分析时自动生成一次，有任务引用、期间与 AI 标识 |
| 多次打开画像或新完成连续发生 | 本地事实即时更新；当天不自动重复分析；保留明确刷新入口 |
| 没有记录或数据不足 | 不生成虚构画像，不把缺记录说成用户不努力，不输出无基线的趋势 |
| 调整目标、导入备份或关闭自动化 | 旧快照请求不能应用；无隐式批量联网，来源记录与用户文字保留 |
| 现有用户拥有十条主线 | 全部保留并可用；成长目标只是新归集维度，不删除或强行重命名主线 |

这些是未来的验收要求，不是已通过的测试记录。

## 12. 分阶段交付与验证假设

1. **完成与归集**：先接受成长目标、未分组任务、完成事件和归属规则，交付自动打标 / 人工纠正闭环。证明完成可靠、分类可改、原数据不丢。
2. **成长反馈**：基于同一完成事实交付目标卡片、个人卡片、成长值与里程碑。证明撤销、改标、拆解、导入都不重复计算。
3. **自动理解**：交付自动推进分析和个人总结、来源追溯、过期标记与费用控制。用真实用户记录验证分类与表达质量，再考虑复杂成长系统。

三阶段是同一产品方向的开发顺序；前两阶段不能宣称完整 AI 画像产品已交付。本次只更新文档，没有实现以上新功能，也不承诺上线日期。

建议招募 5 名同时推进几个生活方向的用户，试用 14 天。以下指标是待审核的试验门槛：

- 用户能在 10 秒内记录一个任务，完成操作不因网络变慢。
- 可明确归类的试用任务中，至少 85% 的自动归类被用户确认合适；歧义任务单独记录，不通过排除所有困难样本伪装准确率。
- 每条 AI 分析的具体事实能追溯任务；错误事实单独记录并修正，不把模型口吻有信心当作准确。
- 至少 3 名用户能从卡片指出一项真实积累，并愿意在下一周继续使用；观察是否主动回看与据此决定下一步。
- 访谈核对：成长反馈是否鼓励行动，是否增加录入负担，是否诱导把任务切碎只为刷分。任务数、停留时长不直接当作产品成功。

采用用户自愿提供的记录与访谈，不新增第三方正文埋点。小样本验证产品假设，不作为市场成功证明。

## 13. 本次重点审核的选择

1. **四个目标是不是固定上限？** 本稿按最多四个启用槽位起草；如果四个只是举例，需改目标布局与上限。
2. **接受“成长目标归集现有多条主线”吗？** 这样能保留旧项目，也允许完成后分类；另一个选项是直接把主线限制为四个，但会增加迁移成本。
3. **升级先采用简单完成值吗？** 建议每条 +10、每 100 升级，不先让 AI 判任务难度；称号和技能树后续验证。
4. **画像表达是否先以行动特点为主？** 例如“近期持续创作的行动者”，带依据、可修改；更强的长期身份标签需要额外定义和验证。
5. **自动分析频率能否接受？** 完成即打标，画像每天一次自动分析最近七日；避免每个勾选都生成四份长报告。

审核反馈直接修改本文。核心方向获得认可不等于每个数值与边界已接受；确认版本后才能更新当前基线与进入开发。
