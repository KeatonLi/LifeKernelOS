# ADR-0002：MVP 采用 React + TypeScript + Vite + Dexie

> 状态：Proposed
> 日期：2026-09-04
> 影响范围：MVP 前端和本地持久化实现

## 背景

LifeKernelOS MVP 是响应式 Web 单体，核心数据保存在浏览器本地。项目当前没有服务端、账号和多端同步需求，首要目标是快速验证行动闭环，同时保证业务规则可以独立测试。

## 决策

- 使用 React 构建页面和交互。
- 使用 TypeScript 表达领域模型、用例契约和错误类型。
- 使用 Vite 作为开发和构建工具，输出静态资源。
- 使用 Dexie 作为 IndexedDB 的基础适配库；Dexie 只出现在 Infrastructure 层。
- 使用 Vitest、React Testing Library 和 Playwright 分别覆盖规则、组件和用户流程。

## 为什么不是更重的方案

### 不采用全栈框架作为首版基础

Next.js 等全栈方案可以提供服务端能力，但 MVP 不需要服务端；引入后会让部署、数据边界和运行模型复杂化。

### 不采用原生多端应用

首轮需要同时覆盖桌面和移动端，响应式 Web 足够验证核心流程，不应提前承担原生打包和分发成本。

### 不让 UI 直接使用 Dexie

这样会把浏览器数据库 API 扩散到页面，未来无法平滑替换为同步仓储，也会让业务规则难以测试。Dexie 只能通过 repository adapter 被使用。

## 代价与接受条件

- 本地数据只存在当前浏览器，跨设备不自动同步。
- Dexie 增加一个依赖，但换来了事务、索引和版本迁移能力。
- 不使用全局状态库，页面间数据刷新必须通过 application 查询重新获取。
- 如果未来加入账号、同步或 AI，必须新建 ADR 和对应规格，不能修改本决策后直接扩展。
