# SPEC-0015 简约行动界面

> 状态：Implemented
> 版本：0.1
> 日期：2026-10-05
> 依据：用户明确要求按新的产品方向先完成简约界面，认可整体风格与色调，指出按钮 UI 过于复杂；界面完成后再研发新功能。
> 对应产品：[PRD v0.11](../../product/PRD.md) 的日常界面与桌面美感范围
> 相关决策：[ADR-0011](../../architecture/decisions/0011-progressive-action-workspace.md) 的已接受日常渐进展示范围；[ADR-0007](../../architecture/decisions/0007-two-tab-console-information-architecture.md)
> 依赖：SPEC-0010、SPEC-0012、SPEC-0013、SPEC-0014
> 目标：让用户先看到任务和清楚的主要操作，减少重复阅读、常驻按钮和首次录入负担，并保留现有处理与恢复能力。

## 1. 用户问题与价值

当前主线页头层次过多，标题、英文眉题、口号与任务信息重复；多个低频处理按钮持续占据视线。列表未选择任务时仍留出空详情区域，创建任务默认露出时长与精力。用户需要更容易理解并操作现有产品，先完成界面减法，再考虑新功能。

本规格沿用冷白、石墨黑与朱橙，靠清楚的层次、紧凑页头和按需展示减轻负担，不通过缩小文字或藏起恢复入口来实现简约。

## 2. 范围

### In scope

- 主线、任务列表、今日、日历紧凑页头与清楚的视图入口。
- 去除日常页面的无操作价值英文眉题、重复口号和重复信息。
- 统一主要、次要、文字和图标按钮的形态、间距、反馈与焦点。
- 当前任务的主要操作保持明确；拆小、卡住、放弃、暂时放下及移除等低频操作按适用状态进入可发现的“更多”菜单。
- AI 拆解保持独立、明确的轻量入口，沿用现有发送预览、生成、采纳与撤销规则。
- 创建及编辑任务的时长、精力按需展开，保留已填值和既有值。
- 任务列表未选择任务时收起空详情，选中后可查看完整内容。
- 菜单、表单及视图入口的键盘、Escape、焦点和既有失败恢复。

### Out of scope

- 新增一级导航、任务视图、AI 场景、回顾、提醒、循环任务或新服务。
- 将画像改为事实概览优先；画像继续以图谱为主画面，事实概览与回顾仍为 Proposed。
- 数据库、DTO、备份版本、日期定义、状态流转、进度公式或当前任务规则变更。
- 重新设计 AI 传输、密钥、建议采纳与撤销的业务契约。

## 3. 领域对象与状态

无新增数据或领域状态。菜单开合、辅助字段展开和选中详情属于界面状态，不写入任务事实。日期继续为本地日历日期；全局最多一个当前任务；进度继续来自完成事实。

当前任务处理按 SPEC-0010 校验 expectedActionId；直接完成、移除与恢复按 SPEC-0013 校验 expectedStatus；AI 仍按 SPEC-0014 校验快照、幂等采纳和撤销保护。视图切换与打开菜单不能隐式写入或改变当前任务。

## 4. 用户流程与显示规则

```text
打开日常视图 → 看任务及主要操作 → 按需打开更多或辅助字段 → 明确处理/保存 → 显示真实结果或可恢复错误
```

1. 左侧继续只有“主线”和“我的画像”两个一级 Tab；快速记下与设置属于辅助入口。主线、列表、今日及日历继续使用同一批任务事实。
2. 每个日常视图保持一个清楚页头与视图切换入口。主线名称只完整出现一次，可放在主线选择器内，并保留标题语义；进度只描述任务完成数与派生比例。
3. 英文装饰眉题、侧栏口号、重复品牌宣言和无额外信息的标题去除。日期、筛选、搜索、撤销与未安排入口仍可发现。
4. 主要按钮承载当前场景的主要动作；次要按钮用于必要的并列操作；轻量辅助动作使用文字按钮；图标按钮用于清楚的图标语义，并提供可访问名称。禁用、忙碌、悬停与键盘焦点有明确反馈，不仅依赖颜色。
5. 当前任务保持清楚的完成操作；需要选择当前任务时保持清楚的选择入口。编辑、返回当前任务与 AI 拆解按既有适用条件可访问。AI 拆解不收进“更多”，用户必须主动点击后才进入既有流程。
6. “更多”入口使用明确可见的文字及展开状态。菜单只显示当前状态允许的操作；移除保留既有确认，拆小/卡住/放弃保留既有输入与处理结果，暂时放下保留释放当前选择的语义。已完成撤销、已移除恢复仍在适用状态清楚可访问。
7. 菜单支持键盘进入与选择。Escape、点击外部、切换任务/视图、进入处理表单或执行操作时关闭；Escape 关闭后焦点回到触发按钮。菜单有可访问名称、展开状态及清楚的焦点，不因关闭菜单改变任务事实。
8. 新建任务先展示标题、主线、内容和日期等当前录入所需字段；预计时长与精力从清楚的辅助入口展开。收起再展开保留草稿；编辑已有任务即使不展开也必须保存既有值，不能默认清空。写入失败保留输入与展开状态。
9. 列表未选择任务时不预留大块空详情列，可显示简短选择提示；选中后展示完整详情。列表选择不等于选择当前任务，已有当前任务的返回入口仍可发现。
10. 写入期间避免重复操作；原有错误、重试、确认、取消、撤销与多窗口冲突反馈保留。正在编辑时继续防止无意切换任务或日期丢失草稿。

## 5. 验收场景

### 场景 A：页头与视图入口

```gherkin
Given 用户已有多个主线及任务
When 用户依次打开主线、任务列表、今日与日历
Then 每个视图的标题及切换入口清楚可见
And 主线名称在主线页只完整呈现一次并保留标题语义
And 没有英文装饰眉题、重复口号或重复整块任务信息
And 当前任务、日期与任务完成事实保持不变
```

### 场景 B：主要操作与更多菜单

```gherkin
Given 用户有一条当前 available 任务
When 用户打开任务详情
Then 完成操作保持清楚且直接可用
And 更多入口可见，拆小、卡住、放弃、暂时放下和移除按既有适用条件可访问
When 用户打开更多并选择一个处理操作
Then 菜单关闭并进入既有处理或确认流程
And 取消不写任务，确认后按既有规则更新任务、当前选择及进度
```

### 场景 C：键盘和菜单关闭

```gherkin
Given 焦点位于更多按钮
When 用户使用键盘打开并选择菜单项
Then 用户能定位并进入允许的操作，焦点清楚可见
When 用户按 Escape 关闭菜单
Then 菜单关闭且焦点回到更多按钮，任务事实不变
And 点击外部或切换任务与视图同样关闭菜单
```

### 场景 D：辅助字段保留

```gherkin
Given 用户新建任务且辅助字段默认收起
When 用户展开、填写时长和精力，再收起并保存
Then 任务保存填写的时长和精力
Given 用户编辑一条已有时长和精力的任务
When 用户只改标题且不展开辅助字段便保存
Then 既有时长和精力保持不变
And 展开/收起与写入失败均不丢失草稿
```

### 场景 E：列表详情按需展示

```gherkin
Given 用户打开任务列表且未选中任务
When 用户查看任务列表
Then 页面不保留大块空详情列，任务列表使用可用空间
When 用户选择一条任务
Then 可读取完整内容并使用适用操作
And 全局当前任务不因列表选择而改变，已有当前任务有返回入口
```

### 场景 F：AI 与恢复入口

```gherkin
Given 用户查看符合拆解条件的任务
When 用户查找 AI 拆解
Then 独立的 AI 拆解入口可见，无需进入更多菜单
And 进入后仍先查看发送上下文，主动生成并明确采纳
Given 用户完成、移除或处理任务时遇到写入失败或旧窗口冲突
When 界面收到错误
Then 已读取事实和已填写输入保留，错误与重试清楚可见，无假成功
And 完成撤销、移除恢复和 AI 结果面板撤销仍按现有条件可访问
```

### 场景 G：布局与按钮层次

```gherkin
Given 应用在支持的桌面窗口尺寸下显示主线、任务列表、今日和日历
When 用户阅读并使用主要、次要、文字及图标按钮
Then 相同类型按钮的形态、间距和反馈一致
And 任务正文、核心操作与视图入口可读且不被裁切
And 选中、当前、卡住及完成可由文字或图标识别，冷白/石墨黑/朱橙风格保持
And 我的画像仍以可追溯图谱为主画面
```

## 6. 空状态、错误与恢复

- 无主线、无任务、搜索无结果、今日为空和未安排为空继续给出对应的简短提示与必要入口。
- 读取失败显示可重试错误，不伪装成空列表；写入失败保留原事实和输入，不显示成功。
- 菜单收起不等于取消未完成表单；取消和移除确认仍由用户明确完成。
- AI 未配置、离线、生成失败、采纳冲突与撤销受保护时继续使用 SPEC-0014 的说明和恢复流程。

## 7. API 与事务边界

无新增 API、IPC、事务或 schema。界面沿用 SPEC-0010/0013/0014 的用例与错误契约；后台业务进程继续是事实源。不得为了简化 UI 绕过业务校验或直接改数据库。
