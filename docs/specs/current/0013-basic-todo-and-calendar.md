> 目标：让用户可靠地记录、安排、完成和调整任务，再用列表、今日与日历查看同一批事实。

## 1. 用户问题与价值

当前任务处理依赖先设为当前行动，日常勾选太重；没有日期就无法知道哪天做什么。先使普通 Todo 易用、可恢复、持久化，再增加 AI。

## 2. 范围

创建、读取、编辑标题/内容/日期，直接完成/撤销完成，可恢复移除，搜索与状态/主线筛选，今日（含之前未处理）、月/周日历，选日新建，跨窗口刷新与备份兼容。

不包含 AI、小时级排期、拖拽、重复任务、提醒、外部日历同步和团队协作。

## 3. 数据与领域规则

1. Action 新增 `scheduledDate: string | null`。真实有效的 1900—9999 年 `YYYY-MM-DD`；不做 UTC 转换。旧记录为 null。
2. available/blocked 可直接完成；completed 可撤销；abandoned 可恢复；superseded 仅保留历史。恢复及完成要求所属主线 active。
3. 状态变更带 expectedStatus，值不一致返回 ACTION_CHANGED。完成/移除只清理指向同一个任务的当前选择。撤销不自动选为当前。
4. 移除需要用户确认，变为 abandoned，默认列表隐藏；恢复重新计入进度。不会删除 Capture、拆分来源或完成主线。
5. 各视图使用同一 Action ID。主线和状态筛选后再应用搜索；默认未完成含 available/blocked。已移除独立筛选。
6. 今日包含日期等于今天和早于今天的未处理任务；未安排不会凭空出现在今日。
7. 月历周一开始且固定 42 天，周历显示 7 天；跨月、闰年与本地时区正确。日期可选、可清除，选定日期新建自动带该日期。
   编辑既有未安排任务不自动填入选定日；拆小默认继承原日期，明确传入日期时替换，null 清除。
8. 月历和周历保留未安排任务入口与选定日任务列表，不因格子截断而丢失访问入口。
9. 请求失败保留已读取事实并显示可重试错误；过期读取不能覆盖更新状态。写入期间防止重复提交。
   编辑期间禁用会切换所选任务或日期的列表和日历控制，避免无意丢失草稿。
10. v7 导出日期，v6 导入补 null；v7 非法/缺失日期与断裂关系拒绝，失败不得替换原数据。

## 4. 验收场景

| 场景 | 可判断结果 |
| --- | --- |
| A 新建/编辑 | 列表、新日期日历和重启后得到相同标题、内容与日期；清除后只在未安排入口出现 |
| B 完成/撤销 | 未设为当前也可勾选；进度实时变化；撤销恢复 available，不抢占当前任务 |
| C 移除/恢复 | 取消确认不写入；确认后默认隐藏；已移除筛选可恢复，内容和日期不丢失 |
| D 多窗口 | 旧状态请求返回冲突，别的当前任务不被释放；用户隔离有效 |
| E 今日/日历 | 过去未处理与今日正确分组；周一首列、闰日、跨月周正确；选日可新建 |
| F 备份/迁移 | 现有 DB 升级不丢数据，v6 兼容，v7 完整往返，非法日期不写入 |
| G 错误/空状态 | 搜索无结果、未安排、今日为空都有说明；读取/写入失败可重试，无假成功 |

## 5. API 与事务

GET `/api/todos` 返回当前用户全部任务。Action 创建/编辑支持 scheduledDate。POST `/api/actions/:id/status` 接收 status（available/completed/abandoned）与 expectedStatus；移除额外 confirmed=true。IPC 与兼容 HTTP 共用服务规则。状态、resolvedAt 与对应当前选择在同一事务提交。进度仍按 SPEC-0010 派生。
